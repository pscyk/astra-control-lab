~/methods

Model calls and policy updates

01

Zero-shot trajectory

Astra returns actions from an instruction and observations. Inputs include calibration and robot state. Prompt development precedes evaluation; the prompt contains no task demonstrations, and model weights stay fixed.

Authored controller

Astra writes Python before execution. The drawer controller reads private simulator state, so it serves as a privileged training teacher. An observation-only policy cannot use those inputs.

~/failures

Grasp and placement failures

The residual repairs 53 base failures but causes four regressions. Random search accounts for much of the gain: RL wins 16 pairs and loses four against that control. The remaining grasp failures need a different correction because the residual only changes later poses.

The feedback run opens one drawer that the one-shot run does not, at a cost of eight extra calls. Its first returned observation differs at the bit level from the baseline's, so this development case cannot isolate the benefit of feedback.

The studies do not test a combined feedback-plus-residual policy. Simulator success does not establish safe contact. These records cover neither the full task suite nor real robots.

~/reproduce

Check the saved results

Playback and result checks need no GPU or model access. Use Python 3.10 or later; the main package needs only the standard library.

python3 -m astra_lab verify
python3 -m astra_lab report
python3 -m astra_lab replay-training
python3 -m unittest discover -s tests -v

These commands check exported records and replay saved training updates. New robot episodes need the original simulator setup and model access; the package includes neither. The logs identify the model as gpt-6-astra but do not verify a fixed backend checkpoint.
